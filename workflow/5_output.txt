Authority
O controls presentation only.
O has no semantic authority.

O may:
- normalize file header layout;
- normalize SCOPE placement and heading;
- generate the Problem-count / populated-Regime-count line mechanically from the controlled Problem set;
- present the controlled Candidates line in its required location without changing its IDs;
- normalize Regime section headings;
- normalize Problem-card field order;
- normalize Case-card field order and placement under the parent Problem;
- normalize line breaks, spacing, representation punctuation, and literal separators;
- normalize TAGS presentation;
- normalize dependency notation presentation;
- normalize COMMENTS presentation;
- normalize version and file-reference presentation;
- enforce the supplied canonical Industry Domain mnemonic in filenames and Problem IDs;
- enforce .txt output.

O must not:
- add, remove, merge, split, or reorder Problems or Cases;
- change Problem IDs, Case IDs, Industry Domain mnemonic, or numbering;
- change Industry, Territory, Domain, Regime, Structure, Parameters, or Descriptors;
- change DESCRIPTION, TEMPLATE, ratings, dependencies, Case type or stage, SOTA, STATE, GAP, proprietary Case findings, TAGS content, COMMENTS claims, or other substantive text;
- infer missing content;
- repair an ontology or evidence defect.

Rules
1. Preserve content exactly except for representation changes allowed above.
2. Use one output layout for every generic Domain and Industry Domain.
3. Preserve literal project syntax. Do not interpret .txt content as Markdown semantics.
4. Present SCOPE before the Problem summary and Problem set.
5. Present one Problem-count / populated-Regime-count line after SCOPE.
6. Present the controlled Candidates line immediately after the Problem-count line.
7. Present Problem cards in their existing controlled order.
8. Insert Regime-band headings only where Problems in that band exist.
9. Use the exact Problem-field order defined by 000_DOMAIN.txt.
10. For LEVEL=CASE, place each controlled Case under its parent Problem and use the exact Case-field order defined by 000_DOMAIN.txt.
11. Do not add absent proprietary Part 2 fields to a Part 1-only Case.
12. TAGS is a separate required field.
13. COMMENTS is a separate required field. Use COMMENTS — when no controlled comment exists.
14. Do not move semantic content between TAGS and COMMENTS.
15. Do not add empty explanatory prose.
16. If required semantic content is absent or inconsistent, stop and return the defect to F/C. Do not supply it.
17. If an ID or ordering defect exists, report it. Do not renumber or reorder.
18. If controlled technical English or other prose requires substantive rewriting, return it to C. O does not rewrite claims.

Finish
Persist the normalized foreground.
No content claim may change during O.
